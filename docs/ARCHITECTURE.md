# Architecture

## Goal

Expose LibreOffice's UNO API to .NET 10 callers through COM. The bridge is native C++ rather than .NET, because the managed UNO bridge (`cli_*` assemblies from the SDK) does not work on .NET 5 and later.

## Layers

```text
 .NET 10 caller (dynamic / early-bound COM)
        │  COM (dual interfaces, IDispatch)
        ▼
 LOBridge.dll     (native/)
   ├─ Dll.cpp          class factories, DllRegisterServer, type library
   ├─ src/writer/      Writer: one .h/.cpp pair per class (App, Document, Paragraph, Range, Table*, Shape, Font, Style, PageSetup)
   ├─ src/calc/        Calc: one .h/.cpp pair per class (App, Workbook, Worksheet, Range, Cell)
   ├─ Zip.cpp/.h       ZIP + DEFLATE reader for .docx packages
   ├─ Config.cpp/.h    appSettings from <dll>.config (GapPageHeight, SetZoomFitWidth)
   ├─ Uno.cpp/.h       bootstrap, session start/stop, property helpers
   └─ Common.cpp/.h    IUnknown/IDispatch boilerplate, BSTR helpers, type library loader
        │  UNO C++ API (generated headers, cppu / cppuhelper / sal)
        ▼
 soffice.exe (separate process, port 2083)  ──  LibreOffice 26.8
```

## Interfaces and IDL

`native/idl/LOBridge.idl` is the single contract:

- Every interface is `[object, dual, oleautomation]` and derives from `IDispatch`.
- The IIDs and the coclass CLSIDs are the same as in the .NET Framework project, so the registration and the type library are interchangeable with the old server.
- `midl` generates `LOBridge.h` (the C++ vtable declarations) and `LOBridge_i.c` (the IID definitions). The `.tlb` is embedded in the DLL as resource 1, and `DllRegisterServer` registers it.

## Dispatch without hand-written tables

Each class uses the macro `LO_COM_IUNKNOWN_AND_DISPATCH(IFACE)` (`native/src/common/Common.h`). It implements:

- `IUnknown` for the one dual interface the class exposes.
- `IDispatch` by asking `ITypeInfo` (from the embedded type library) to invoke the call through the dual vtable.

`QueryInterface` accepts `IUnknown`, `IDispatch` and the class's own interface. Nothing else is exposed.

## Object model

Each COM object wraps UNO objects with `css::uno::Reference<>`:

| COM object | Wraps |
| --- | --- |
| `WriterApp` / `CalcApp` | `lo_uno::Session` (context, desktop, loader) |
| `writer::Document` | `XTextDocument` |
| `writer::Paragraph`, `WordRange` | `XTextRange`, `XText` plus the property set of the range |
| `WordTable`, `WordTableRow`, `WordTableColumn`, `WordTableCell` | `XTextTable` plus the row, column or cell by index or name |
| `WordShape` | `XShape` (text frame or drawing shape) |
| `WordStyle`, `WordFont`, `WordPageSetup` | `XPropertySet` of the style, text or page style |
| `calc::Workbook`, `calc::Worksheet`, `ExcelRange`, `ExcelCell` | `XSpreadsheetDocument`, `XSpreadsheet`, `XCellRange`, `XCell` |

Reference counting follows COM rules. A method that returns a new object creates it with refcount 1 and hands that reference to the caller (`ReturnNew`). Internal helpers that need a temporary object create it on the stack or with the `Scoped<>` helper and release it immediately.

Internal objects keep UNO references rather than COM pointers, so a caller releasing a table does not invalidate the cells it already obtained.

## Office session

`StartSession` (`native/src/uno/Uno.cpp`):

1. Calls `WSAStartup` once (the socket connector needs Winsock).
2. Bootstraps the local UNO context. `URE_BOOTSTRAP` is set to the 8.3 short path of the office's `fundamental.ini` so the registries load (see [TROUBLESHOOTING.md](TROUBLESHOOTING.md) §1).
3. Resolves `uno:socket,host=localhost,port=2083;urp;StarOffice.ComponentContext`. If nothing is listening, it starts `soffice.exe --headless ...` with a private profile and retries for about 60 seconds.
4. Creates `com.sun.star.frame.Desktop` through the remote service manager.

`EndSession` releases the references only. The office may be shared with other callers, so it is not terminated.

## Errors

UNO exceptions are caught by `LO_COM_TRY` / `LO_COM_CATCH`, logged with `lo_com::LogException`, and returned as `E_FAIL`. Winsock and bootstrap failures are logged the same way.

## Compatibility with the .NET Framework library

The original C# sources are kept in `reference-dotnet/` for comparison. Behaviour is ported method by method. Deliberate differences are listed in [API.md](API.md#differences-from-the-net-framework-library).
